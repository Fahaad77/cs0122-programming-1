Section 01

What Is Programming?

Start with the process before writing code.

Concept

What is a computer program?

A program is a set of commands written by a programmer in a programming language to solve a problem or perform a task.

A good program starts as a clear idea, then becomes code that can be tested and improved.

Visual Model

The programming process

Plan->Design->Code->Compile->Run->Test / Debug->Maintain

Beginners often want to jump to code. Professional programmers move through the whole cycle.

Concept

Six kinds of program instructions

InputRead data.
ProcessingCalculate or transform data.
LogicalChoose between paths later.
RepetitionRepeat work later.
OutputDisplay results.
StorageSave values in memory or files.

Concept

Programming languages communicate with computers

Programmer

Writes clear commands using syntax rules.

User

Runs the program and benefits from its results.

Java is one high-level language used to write these commands.

Section 02

Meet Java

A high-level language that becomes portable bytecode.

Visual Model

Human-readable vs machine-readable

Human idea->High-level source code->Translated form->Machine work

Computers ultimately execute low-level instructions. High-level code must be translated.

Vocabulary

Source program and target program

Source code

Written by humans. In Java, source files end with .java.

Target code

Translated form produced from source code. In Java this is usually bytecode.

Translate

Compiler vs interpreter

CompilerInterpreter
Translates a program before execution.Executes instructions step by step.
Finds many syntax errors before running.Works during execution.

Java uses both ideas: compile to bytecode, then run through the JVM.

Java

Why Java?

SimpleReadable syntax and many helpful libraries.
Object-orientedCode can be organized into classes; deeper object ideas come later.
Platform independentBytecode can run anywhere a matching JVM exists.
SecureThe JVM checks code before and during execution.
DynamicJava can load needed classes while a program runs.

Java Platform

Which Java edition do we use?

Java SE

Core Java for console and desktop programs. This is the Programming 1 focus.

Java EE / ME

Enterprise/web systems and small-device editions. Useful context, not our first-week toolset.

Section 04

JDK, JRE, JVM

Separate the tools that build Java from the runtime that executes it.

JVM

The JVM is a virtual computer

The Java Virtual Machine executes bytecode, manages runtime behavior, and hides many operating-system differences from the Java program.

Bytecode is not executed directly by the CPU. It runs through the JVM.

JRE

JRE: runtime environment

The Java Runtime Environment provides what is needed to run Java programs: JVM plus core Java libraries.

The JRE is for running Java applications, not for writing and compiling them.

JDK

JDK: developer kit

JDK developer tools, including javac
JRE runtime libraries and JVM
JVM executes bytecode

Development Environment

What tools do we need?

Compiles and runs Java programs.

VS Code

IDE features students should notice

  • Syntax highlighting shows code structure.

  • Auto-completion reduces typing errors.
  • The terminal runs javac and java.

Main method and parameters

public static void main(String[] args) {
  // statements run from top to bottom

String[] args is the parameter list for command-line words. For now, keep it exactly as shown.

Syntax

Statements end with semicolons

System.out.println("One statement");
System.out.println("Another statement");

Java is case-sensitive. System, system, main, and Main are not the same.

Section 06

Errors and Debugging

Learn what Java tells you before, during, and after execution.

Debug

Syntax error

System.out.println("Hello CS0122")

Meaning

Java grammar is broken.

Student observes

The compiler reports an error before the program runs.

Debug

Runtime error

System.out.println(10 / 0);

Meaning

The code compiles, starts, then fails while running.

Student observes

The terminal prints an exception message.

Debug

Logical error

System.out.println("Total: " + 5 + 2);

Meaning

The program runs, but the answer is not what you intended.

Student observes

No compiler error; output must be checked against expectation.

Checkpoint
